# نسق — Nasaq

**نظام واجهات قابل للتوسعة، يدعم العربية من الأساس، ويستهدف JavaScript دون إطار عمل وReact وVue وAngular.** يمنح نسق المنتجات هوية بصرية مستقلة، وسلوكًا مشتركًا للمكونات، وأنماطًا قابلة للتعديل لبناء رحلات خدمات متكاملة.

[الدليل التفاعلي](https://mohamedembarak.github.io/nasaq/) · [المستودع](https://github.com/MohamedEmbarak/nasaq) · [English](README.md) · [نطاق التغطية](docs/coverage.md) · [البنية](docs/architecture.md) · [دليل التوسعة](docs/extension.md) · [سجل التحقق](docs/validation.md) · [دليل المساعدات البرمجية](llms.txt)

تجمع هوية **Woven Rhythm** الأخضر المزرق والعاجي الدافئ مع شعار كتابي عربي فقط هو **نسق**. تستخدم كتابة الشعار **Aref Ruqaa Bold محوّلًا إلى مسارات SVG**، فلا يحتاج عرضه إلى تحميل الخط. تبقى خطوط الواجهات IBM Plex Sans Arabic وIBM Plex Sans. يتضمن [دليل الهوية المحلي](brand/index.html) و[إرشادات الشعار](brand/README.md) و[حزمة الهوية ZIP](brand/nasaq-brand-kit.zip) الشعار ومؤشرات تحميل تحرّك حروفه بخلفية شفافة.

معاينات: [المعرض بالعربية على الهاتف](docs/previews/playground-ar-mobile.png)، و[استوديو التخطيط](docs/previews/layouts.png)، و[منتقي التاريخ الميلادي وأم القرى](docs/previews/date-picker.png).

يستفيد نسق من إرشادات **هيئة الحكومة الرقمية — DGA** و**كود المنصات — Platforms Code**، وهو **نظام التصميم الموحد — Unified Design System** في **المملكة العربية السعودية — Kingdom of Saudi Arabia (KSA)**، في الأسس المناسبة وتجارب الخدمات الحكومية، مع تصميمه ومكوناته وتركيباته الخاصة. **تُوثَّق مواءمة DGA compliance بالأدلة والفجوات. نسق تنفيذ مستقل، ولا يدّعي اعتمادًا رسميًا أو تصديقًا من الهيئة.** راجع [توثيق المواءمة](docs/alignment.md) قبل وصف أي منتج بأنه متوافق.

## حالة التطوير

المشروع متاح المصدر في **مرحلة تطوير 0.1** بترخيص Apache 2.0. تدعم الحزم السبع **فهرسًا من 77 مكونًا** عبر vanilla وReact وVue وAngular، يشمل النماذج والتفاعل والمحتوى وأنماط الخدمات السعودية و12 مكونًا للتخطيط. أسماء الحزم مبدئية، ولم تُنشر الحزم على npm. وجود شفرة أو مثال يعمل لا يعني اكتمال الجاهزية للإنتاج.

تفصل [خريطة الطريق](docs/roadmap.md) بين المخطط والمنفذ والمتحقق منه. يعرض [components.json](components.json) هذه الحالات أيضًا بصيغة قابلة للقراءة آليًا. تُراجع تغطية كل إطار عمل والتحقق الفعلي من الفهرس، ولا تُستنتج من أسماء الحزم.

## اتجاه النظام

- هوية نسق الخاصة، وسمة مرجعية اختيارية مستندة إلى DGA، وإمكان إنشاء سمات مخصصة.
- العربية والإنجليزية، مع استقلال اللغة عن اتجاه العرض، واستخدام خصائص CSS المنطقية لدعم RTL وLTR.
- مكونات بواجهات برمجية طبيعية لكل إطار، تشترك في قيم التصميم والتنسيق ومنطق التفاعل.
- HTML وCSS قابلان للاستخدام دون JavaScript حيث تسمح طبيعة المكون، مع تفعيل واضح للسلوك التفاعلي.
- مكونات أساسية، وكتل قابلة للتحرير، وأمثلة لرحلات اكتشاف الخدمة وتقديم الطلب ومراجعته وإدارته.
- مختبر لأنواع إدخال HTML الأصلية الـ22، وأنماط البيانات السعودية، وتركيب التخطيطات المتجاوبة.
- تقويم ومنتقي تاريخ للميلادي وأم القرى، بقيم تاريخ مستقلة عن الوقت ومرجع بيانات موثق.
- نقاط توسعة موثقة، وشفرة مفهومة، وأنواع واضحة تساعد التطوير اليدوي والتطوير بمساعدة الذكاء الاصطناعي.

## الحزم

| الحزمة | المسؤولية |
|---|---|
| `@nasaq/tokens` | قيم التصميم والمتغيرات الدلالية للسمات |
| `@nasaq/styles` | تنسيقات المكونات وأدوات التخطيط وملف reset اختياري |
| `@nasaq/core` | منطق مشترك مستقل عن الأطر وأدوات اللغة والتنسيق المحلي |
| `@nasaq/vanilla` | متحكمات تضيف التفاعل إلى HTML مع إتاحة إزالة التفعيل |
| `@nasaq/react` | مكونات React تستخدم الأساس المشترك |
| `@nasaq/vue` | مكونات Vue تستخدم الأساس المشترك |
| `@nasaq/angular` | مكونات Angular تستخدم الأساس المشترك |

تظل الحزم السبع موسومة بـ `private: true` لمنع النشر غير المقصود على npm أثناء تطوير الواجهات البرمجية. الشفرة متاحة في المستودع العام. ترتبط كل حزمة إطار بتبعياتها، ولا يعتمد المنطق المشترك على بيئة تشغيل أي إطار.

## التشغيل محليًا

من مجلد المشروع، استخدم إصدار pnpm المحدد في `package.json`. أُجريت فحوص التطوير باستخدام Node.js `24.19.0` وpnpm `11.25.0`:

```sh
git clone https://github.com/MohamedEmbarak/nasaq.git
cd nasaq
pnpm install
pnpm build:packages
pnpm dev
```

تبدأ بيئة التطوير بمعرض vanilla. افتح `#components` لفهرس المكونات، و`#inputs` لدلالات الإدخال، و`#layouts` لتركيب التخطيطات. يتضمن المعرض دليل الهوية المحلي. لتشغيل مثال إطار بعد بناء الحزم:

```sh
pnpm --filter @nasaq/example-react dev
pnpm --filter @nasaq/example-vue dev
pnpm --filter @nasaq/example-angular dev
```

اختر المثال المطلوب؛ كل أمر يشغّل خادم تطوير مستقلًا. تشمل الفحوص `pnpm build` و`pnpm typecheck:playground` و`pnpm test` و`pnpm test:browser` و`pnpm check:packages`. تُوثَّق النتائج وإعداد المتصفح في [سجل التحقق](docs/validation.md). أدلة الواجهات البرمجية: [vanilla](packages/vanilla/README.md)، و[React](packages/react/README.md)، و[Vue](packages/vue/README.md)، و[Angular](packages/angular/README.md).

## مثال HTML

```html
<section lang="ar" dir="rtl" data-nq-theme="nasaq"
         data-nq-mode="light" data-nq-density="comfortable">
  <div class="nq-card">
    <div class="nq-card-body">
      <h2>طلب جديد</h2>
      <p>راجع متطلبات الخدمة قبل البدء.</p>
      <button class="nq-button" data-variant="primary" type="button">
        ابدأ الطلب
      </button>
    </div>
  </div>
</section>
```

تُحمَّل التنسيقات في التطبيق المستهلك:

```ts
import '@nasaq/styles/styles.css';
```

ملف `@nasaq/styles/reset.css` اختياري، ويُحمَّل قبل تنسيقات المكونات عند الحاجة. يوثق [عقد التفاعل](packages/core/API.md) و[دليل توسعة vanilla](packages/vanilla/EXPANSION-API.md) بنية HTML وواجهات التفعيل. يتولى كل إطار إدارة عناصره؛ لذلك لا يُفعَّل متحكم vanilla فوق شجرة مكونات يديرها React أو Vue أو Angular.

## التعديل والتوسعة

عدّل السمة لتغيير المظهر العام، واستخدم الخيارات الموثقة لتغيير مظهر المكون، وركّب المكونات لتلبية احتياجات المنتج. ابدأ من [الكتل القابلة للتحرير](blocks/README.md)، أو شغّل `pnpm new:component request-summary` لإنشاء كتلة يملكها التطبيق داخل `blocks/`. ينشئ الأمر HTML وCSS وإرشادات؛ ولا ينشئ مكون مكتبة جديدًا لكل إطار. التفاصيل في [دليل التوسعة](docs/extension.md).

للمساعدات البرمجية: ابدأ بقراءة [AGENTS.md](AGENTS.md) و[CONTRACT.md](CONTRACT.md) و[EXPANSION.md](EXPANSION.md) و[llms.txt](llms.txt) والفهرس. اعتمد الصادرات الفعلية والأمثلة، وحافظ على التسميات والتنقل بلوحة المفاتيح ورسائل الخطأ ودعم الاتجاه عند التعديل.

## حدود النسخة الحالية

يدعم Combobox البحث المحلي واختيار قيمة واحدة، بينما يقدم MultiSelect قائمة مستقلة بمربعات اختيار قابلة للبحث. يدعم DataTable الفرز المحلي المستقر؛ وتحتاج الجداول الافتراضية أو القابلة للتحرير إلى محرك متخصص. يختار FileUpload وFileDropzone الملفات؛ أما نقلها وتخزينها فمن مسؤولية التطبيق. تجمع أنماط الهاتف وIBAN والهوية البيانات دون إثبات الهوية أو ملكية الحساب. يحدد [دليل التغطية](docs/coverage.md) النطاق، ويوضح [دليل التكاملات](docs/integrations.md) حدود الخرائط والرسوم والمحررات والمصادقة والدفع.

يخزّن Calendar وDatePicker قيمًا ميلادية بصيغة ISO `YYYY-MM-DD`، مع عرض ميلادي أو وفق أم القرى. يعتمد التحويل الهجري على جدول مرجعي مثبت الإصدار بحدود صريحة. راجع [موثوقية التقويم](docs/date-calendars.md) قبل استخدام تاريخ مشتق في سجل رسمي. تستخدم الأمثلة بيانات وهمية وتحاكي إرسال الطلبات وتتبعها.

يعتمد السلوك المشترك على أدوات مستقلة عن العرض ومختزِل صغير لحالة Combobox طُوّرا داخل المشروع، دون الاعتماد على Zag. تُبنى مكتبة Angular بصيغة Angular Package Format، بينما يستخدم مثال Vite وضع JIT عمدًا؛ ولا يثبت المثال تغطية AOT الإنتاجية أو SSR أو hydration. راجع [البنية](docs/architecture.md) و[دليل Angular](packages/angular/README.md).

## الجودة والنشر

الهدف الهندسي للإتاحة هو **WCAG 2.2 AA**، مع فحص لوحة المفاتيح والتقنيات المساعدة والتباين وتقليل الحركة. هذا هدف جودة، وليس إعلانًا بأن جميع الأمثلة اجتازت تدقيقًا كاملًا. تحدد [خريطة الطريق](docs/roadmap.md) بوابات التحقق من الحزم والأطر ورحلات الاستخدام.

يحدد [سجل التحقق](docs/validation.md) النسخة المفحوصة والأوامر ونتائج استهلاك الحزم وحالات السلوك وhydration ورحلات Chromium. يفصل [الفهرس](components.json) التنفيذ عن التحقق لكل مكون؛ ولا تثبت فحوص النسخة السابقة تلقائيًا سلوك الإضافات اللاحقة. لم يُستكمل بعد الاختبار اليدوي بقارئات الشاشة أو التحقق عبر عدة متصفحات.
