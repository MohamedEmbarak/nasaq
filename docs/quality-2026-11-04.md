## What the catalog checks establish

The manifest and editor registry contain the same 83 entries after resolving two public guide aliases: `upload` corresponds to FileUpload and `empty` to EmptyState. All 1,162 component, format and locale combinations generated complete project files. Chromium exercised 581 distinct component/format combinations on the production snapshot. The matrix opens the actual editor, loads the selected adapter and checks rendered controls or an appropriate trigger. Dedicated feature suites exercise the more detailed keyboard, form, mobile and accessibility behavior.

The universal editor run covered 156 test groups. Its first pass completed 151 groups successfully; five groups encountered local server availability or cold-start failures. All five passed on the same production files with the same assertions on replay. Separate React, Vue and Angular consumer apps passed 27 scenarios each. The served JavaScript files matched the production outputs by SHA-256. Three Vue consumer scenarios exceeded the initial 30-second total scenario limit and passed with a 90-second limit and unchanged assertions.

The full unit suite passed all 620 tests in 113 files in one run, using Node 24.21.0 and Vitest 5.0.5 with one worker.

The contrast suite passed all eight token checks. WebKit verified production layout direction at 320px and 1280px with language and direction set independently. Its rating checks exercised both Arabic and English, including four automated accessibility scans across light and dark examples.

## Source decisions and boundaries

- The [foundations comparison](nic-foundations.md) separates declared variables from computed values. At a 16px root, 14 text size and line-height pairs matched the supplied CSS in fixtures at 390, 768 and 1280px. The large-card padding variable resolves to 24px at desktop width. The base card uses a different variable and measures 16px.
- [Select](nic-select.md), [search](nic-search.md), [notification patterns](nic-notifications.md), [semantic lists](nic-lists.md) and [grouped portal navigation](nic-portal-navigation.md) include examples, state behavior, measured values and source limits. Host routes, search data and consent persistence remain application-owned.
- The custom DatePicker accepts typed Gregorian ISO dates and opens Nasaq's picker from its calendar icon. The active calendar controls the display. The pinned Umm al-Qura calculation and supported range remain the source of date conversion. Firefox 159 on Windows verified entry of `2026-11-08`, unchanged ISO selection on a Gregorian/Hijri round trip, return focus, password reveal/conceal and identical dialog bounds in the two calendar modes.
- The original theme, custom themes, Latin digits, Arabic-first copy, outlined Nasaq wordmark, NIC light/dark logo treatment, meaningful keyboard focus and reduced motion remain explicit product decisions. The ready gallery and inline demos contain their navigation. Downloaded projects show where applications connect real routes and handlers.
- The 23-file Figma inventory includes the application-specific Hajj design for provenance. Hajj features are outside the package scope. No standalone official web Components Library export was supplied. The visual fixtures and browser checks do not determine redistribution rights for official artwork. The reports distinguish Nasaq-authored and independently licensed substitutes.

These are implementation and test results for Nasaq's documented scope. DGA certification, exhaustive official pixel parity, physical iOS and Android testing, and a manual screen-reader audit are separate activities.
