# Quality follow-up — 2026-11-02

This report covers the input-height and validation follow-up, plus the broad
regression run over the guide and native React, Vue and Angular consumers.
The guide exercises vanilla composition/controllers. Hajj is excluded.
These are scoped implementation checks, not official DGA certification or
evidence that every possible component/state/framework combination is covered.

## Fixes

| Finding | Resolution | Regression evidence |
| --- | --- | --- |
| Short fields stretched to match taller neighboring form content; the guide number input reached 114px instead of its 40px default | Field content aligns to the start of its grid area; multiline controls retain their own sizing | Guide Arabic/English at 1800/1100/390px; all three native consumers at comfortable/mobile/compact densities |
| Initially populated valid fields did not receive green focus treatment until edited | Adapter-owned value-presence tracking combines nonempty values with native validity; reset and controlled updates refresh it | Core lifecycle tests, four-adapter input parity tests, four guide color cases and three native color cases |

| Embedded portal skip link obscured part of a catalog heading | Clip the link until focus; retain visible keyboard reveal and focus the embedded preview target without leaving the guide | New keyboard regression and both English/light and Arabic/dark component-gallery axe scans |
| Dialog regression waited for the former input-group button | Locate the custom date-picker trigger | Content/backdrop drag, intentional dismissal, Escape and focus restoration pass in React, Vue and Angular |
| Compiled unit-test output entered a local core tarball during development | Move the test outside the production source tree; reject compiled test/spec files during package checks | Clean tarball verification passes with no test output |

The validation colors are a product-approved adaptation. Green appears only
while focused, including for initially populated valid values. Empty fields
remain dark neutral; native user-invalid or explicit application errors are red.
Applications own the timing of their explicit errors. The value tracker does
not calculate validity or change submitted values. Read-only keyboard focus,
forced colors, reduced motion and original/custom themes remain supported.
See [the field contract](input-validation-colors.md).

## Reproduce

Build before running native consumer previews. Set `NASAQ_CHROMIUM` to an
installed Chrome/Chromium executable, or install Playwright's managed Chromium.
Run the suites sequentially on resource-constrained machines.

```sh
pnpm build
pnpm test --pool=forks --maxWorkers=1
pnpm exec playwright test --workers=1 --timeout=90000
pnpm exec playwright test --config playwright.portals.config.ts --timeout=90000
pnpm check:packages
pnpm build:docs
```

For GitHub Pages, set `NASAQ_BASE_PATH=/nasaq/` before the docs build. Test logs,
traces, screenshots and tarballs stay local and are excluded from Git.
