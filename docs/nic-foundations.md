# NIC foundations in Nasaq

The comparison uses the supplied NIC `global.css` snapshot. Its hash, retrieval details and mapped component owners are in the [source inventory](nic-web-reference.md). The [Figma foundations reference](dga-reference.md) remains the record of the supplied local variables. The NIC stylesheet and Figma source sometimes assign different shadows or line heights to the same named size.

| Source and observed value | Current Nasaq mapping | Evidence and limits |
| --- | --- | --- |
| CSS 1–31 declares IBM Plex Sans Arabic regular, medium, semibold and bold using four local URLs and weights 400–700. | The font stack starts with IBM Plex Sans Arabic. Components express weight numerically. The host can supply the typeface through its stylesheet. | Family and weight are decoded CSS properties. The fixture blocked network requests and does not establish identical glyph rendering. |
| CSS 34–77 supplies spacing from 0 to 1920px, width names from 320 to 1920px and a 720px paragraph measure. | The shared spacing and width variables include the half steps (2 and 6px), large steps, eleven named widths and `--nq-width-paragraph`. Values in rem respond to the user's root text size. | At a 16px root the values match the source dimensions. Existing responsive grid and container APIs retain their documented breakpoints. |
| CSS 90–190 defines desktop, tablet and phone aliases. The tablet rule follows the desktop rule and also matches desktop widths. Some fractional references use an ASCII period while their definitions contain U+2024. | Nasaq provides valid ASCII names such as `--nq-space-0-5`. Component dimensions use their own verified geometry instead of depending on unresolved aliases. | A Chromium fixture measured 16px, 24px and 24px for the source large-card padding at 390, 768 and 1280px. The source fractional alias fell back at all three widths. |
| CSS 193–207 specifies 0, 2, 4, 8, 16, 24px and pill corners. CSS 327–333 specifies seven elevations. | `--nq-radius-none` and `--nq-radius-xs` complete the corner scale. `--nq-shadow-xs` through `--nq-shadow-3xl` expose the measured web definitions under DGA and custom themes. Original Nasaq retains its previous small, medium and large elevations. | Declared values have high confidence. Visual depth also depends on the surrounding surface and contrast mode. |
| CSS 210–425 maps neutral, flag green, gold, lavender and status primitives into light and dark text/surface roles. | DGA light uses primary #1B8354, text #161616, canvas #F9FAFB and surface #FFFFFF. Dark uses canvas #111927, surface #1F2A37 and text #FFFFFF. Semantic token overrides allow custom palettes. | The guide names swatches by their role. Component-specific contrast choices are recorded in the linked component reports. |
| CSS 427–571 defines six display scales, 20/18/16px headings and five body scales. Examples include 72px/90px display and 12px/14px body. | Apply `nq-type` with `data-scale`: display-2xl through display-xs, heading-lg/md/sm, or body-xl through body-xs. The HTML heading level remains the author's decision. `--nq-type-spacing` and `--nq-type-weight` override the preset. | The 14 size/line-height pairs matched the isolated source fixture at 390, 768 and 1280px. The selector applies only to elements that request it. |
| CSS 575–605 defines 1, 2, 3, 4 and 10-line excerpts. | `nq-line-clamp` and `data-lines` leave the full string in the DOM. The guide provides a disclosure for sighted users to read the full excerpt. | No JavaScript truncation or locale-dependent string slicing. |
| CSS 610–850 provides text, background, shadow, radius and divider treatments. The divider is 1px with neutral, primary, gold or lavender coloring. | Components use public semantic CSS variables for color, radius and elevation. Divider supports four tones through native adapter props or `data-tone`, plus a vertical orientation for inline groups. | Tones follow the NIC light values. Dark, original and forced-color modes retain their own palettes. Grouping information should also be clear from structure and spacing. |

The [Foundations guide](https://mohamedembarak.github.io/nasaq/#foundations) shows the type scale, an expandable excerpt and all seven elevations. The [Divider guide](https://mohamedembarak.github.io/nasaq/#component/divider) shows the four tones and a vertical composition. High-contrast support uses local system color and focus rules. The NIC site's global image filters, host font endpoints and SharePoint resets are outside the component API.

Six Chromium scenarios passed against the built guide. Arabic/light and English/dark at 390px and 1280px matched all 14 font-size and line-height pairs. The accessibility tree retained the full excerpt. Original and custom themes, independent text direction, forced colors and visible vertical rules were exercised across the four adapter projects.
