# Notification banner

The source measurements below use the HTML emitted by `showNotification` in the supplied NIC JavaScript and the supplied stylesheet. The inline styles change several stylesheet defaults. The comparison rendered isolated fixtures at 1280, 390 and 320 CSS pixels in both directions, with external requests blocked. The source hashes are in the [reference inventory](nic-web-reference.md).

| Source | Measured or declared behavior | Nasaq mapping |
| --- | --- | --- |
| CSS 3846–3876 and JS 358–391 | The desktop banner begins 80px below the viewport top and 20px from the inline end. Emitted markup sets a 450px maximum width, square corners, 16px by 24px padding, a two-layer shadow and a 2px bottom border. | The optional banner variant uses these dimensions. Applications can set `--nq-toast-header-offset` and choose a corner or inline placement. |
| JS 324–356 | Success, warning, error, info and neutral each have a text, surface and border color. The glyph is 20px and the message uses 14px text with 21px line height. | The public error tone is named `danger`. The light DGA palette follows the emitted colors. Dark and original themes use semantic pairs. Status artwork is independently drawn, decorative and colored with the message. |
| CSS 3797–3843 and 3957–3967 | The banner enters from the inline end over 300ms with ease-out. At widths up to 576px the top becomes 70px and both inline offsets are 10px. The source fixture overflowed the viewport by 10px when its emitted width overrode the stylesheet. | Nasaq reserves the two gutters when calculating width, uses the writing direction for entry and honors reduced motion. |
| JS 318–412 | The site replaces its previous notice, announces every notification assertively and uses a four-second default timeout. | Applications own the collection and its lifetime. Only explicitly urgent messages enter the assertive region. A protected notice has no dismiss action. |
| Dismissal and focus | The source removes the banner after fading it. Earlier Nasaq controlled dismissals could leave keyboard focus on the page body when another notice remained. | The adapters recover focus after accepted removal, trying a following action, a preceding action and the labelled region. If the application retains the message or moves focus, the adapter respects that choice. |

Use the inline position when embedding the example in an existing page. The [ToastRegion guide](https://mohamedembarak.github.io/nasaq/#component/toast-region) supplies working examples for all four adapters, including five tones, interactive dismissal and restoration. Notification dialogs are a separate composition. The stylesheet and emitted markup establish geometry and colors. The original icon glyphs and the browser rendering of the site's jQuery fade were outside the fixture.

Fifteen focused behavior tests cover the four adapters. Two bilingual guide scenarios and seven native editor scenarios cover dismissing and restoring messages, retained focus, source geometry, 320px containment, forced colors and reduced motion. The 20px close artwork uses the existing licensed cancel icon. Banner shape checks and light/dark contrast checks use the actual rendered elements.
