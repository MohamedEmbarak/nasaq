# Public portal layout

Use the shared shell classes with semantic HTML. Header, secondary navigation,
breadcrumb, main container and footer are available without a page-specific
template. `enhance()` owns only marked vanilla trees. Navigation stays visible
without enhancement: do not put `hidden` or `data-open="false"` in initial HTML.

```html
<div class="nq-portal-layout" lang="ar" dir="rtl">
  <header class="nq-portal-header" data-nq="portal-header">
    <a class="nq-skip-link" href="#portal-content">انتقل إلى المحتوى</a>
    <a class="nq-portal-brand" href="/">نسق</a>
    <button class="nq-button nq-portal-menu-toggle" type="button" data-nq-portal-toggle>
      <span class="nq-icon" data-icon="menu-01" aria-hidden="true"></span>القائمة
    </button>
    <nav aria-label="التنقل الرئيسي" data-nq-portal-navigation>
      <ul><li><a href="/services" aria-current="page">الخدمات</a></li></ul>
    </nav>
  </header>
  <nav class="nq-secondary-nav" aria-label="التنقل الثانوي">
    <ul><li><a href="/services" aria-current="page">دليل الخدمات</a></li></ul>
  </nav>
  <main class="nq-portal-layout-main nq-container" id="portal-content" tabindex="-1">
    <nav class="nq-breadcrumb" aria-label="مسار التنقل"><ol>
      <li><a href="/">الرئيسية</a></li><li><span aria-current="page">الخدمات</span></li>
    </ol></nav>
    <h1>الخدمات</h1>
  </main>
  <footer class="nq-portal-footer"><strong>نسق</strong>
    <nav aria-label="روابط التذييل"><ul><li><a href="/privacy">الخصوصية</a></li></ul></nav>
  </footer>
</div>
```

```ts
import { enhance } from '@nasaq/vanilla';
import '@nasaq/styles/styles.css';
const dispose = enhance(document.querySelector('.nq-portal-layout')!);
// Dispose before replacing the shell.
```

For direct control, `createPortalHeader(header, { onOpenChange })` returns
`open`, `show()`, `close(restoreFocus?)` and `destroy()`. Escape closes the mobile
navigation and returns focus to its toggle. Selecting a link, moving focus out,
or pressing outside closes it; Tab retains native navigation. The desktop links
remain visible. IDs generated by enhancement are removed on cleanup, and the
original attributes are restored. Use distinct main IDs for multiple shells.

Use a native `details[data-nq-portal-branch]` inside the navigation for a group of links.
The summary stays keyboard-operable before enhancement. A flat branch can contain a single
list. For a grouped panel, give each list a visible heading.

```html
<li>
  <details class="nq-portal-branch" data-nq-portal-branch>
    <summary>الخدمات</summary>
    <div class="nq-portal-branch-panel">
      <section class="nq-portal-branch-group">
        <h2>التراخيص</h2>
        <ul>
          <li><a href="/licenses/new" aria-current="page">إصدار ترخيص</a></li>
          <li><a href="/licenses/renew">تجديد ترخيص</a></li>
        </ul>
      </section>
    </div>
  </details>
</li>
```

Opening a sibling summary closes the previous branch. Escape closes the innermost open
branch and focuses its summary. A subsequent Escape closes the mobile navigation when
its toggle is expanded. Moving focus or pressing outside a branch dismisses it. Links
retain their native activation. Set `aria-current="page"` on the destination selected by
your router. Group order, labels, URL normalization and any optional artwork belong to
the host application.

The NIC reference emits flat link lists and grouped columns in `master.js` lines 733–765
and handles outside clicks and mobile toggles in lines 873–925. Its site-specific IDs,
session storage and remote image URLs are unnecessary for this composition. Use artwork
with redistribution terms appropriate to your application. [NIC reference and provenance](../../docs/nic-web-reference.md)

The 48rem mobile disclosure breakpoint is a Nasaq adaptation. The source audit
supports the header/navigation/footer composition; this is not a claim of exact
pixel or official certification parity. Set `lang="en" dir="ltr"` and translate
all labels for English; direction remains independent from language. All themes
use semantic tokens. The layout itself adds no animations.

## Mobile navigation bar

Use `variant="mobile"` on `SecondaryNav` (React/Vue) or `nq-secondary-nav`
(Angular). Items accept an optional decorative `icon` name from the bundled icon
stylesheet, such as `home-01`, `search-01` or `menu-01`; labels remain required.
Vanilla uses `data-variant="mobile"` and the same semantic HTML:

```html
<nav class="nq-secondary-nav" data-variant="mobile" aria-label="تنقل الجوال">
  <ul>
    <li><a href="/" aria-current="page"><span class="nq-icon" data-icon="home-01" aria-hidden="true"></span><span>الرئيسية</span></a></li>
    <li><a href="/services"><span class="nq-icon" data-icon="search-01" aria-hidden="true"></span><span>الخدمات</span></a></li>
  </ul>
</nav>
```

The bar uses equal-width items, 24 px icons, a 70 px minimum height, wrapped labels
and a top current-page indicator. It is in normal flow and does not cover page
content. Safe-area bottom padding accommodates mobile devices; the source OS
home indicator is not reproduced. The application owns route/current updates.
These are page links, not content tabs: preserve native Tab/Enter navigation.

DGA/custom color transitions use `--nq-duration-tab-bar: 300ms` and
`--nq-ease-tab-bar: cubic-bezier(0, 0, 0.58, 1)`. Nasaq remains immediate by
default. Reduced motion removes transitions; forced colors retains the selected
top border and keyboard focus. Hover does not mark a route selected.

Source Mobile `8332:24202` → `8332:24242` → `8332:24282` supports color changes,
not a sliding indicator or tab-panel animation. Semantic colors adapt to theme;
icon color follows the label, since imported icon override endpoints were not
resolved. Arabic width differs from English in the source, so no fixed item
width is imposed. This is a source-informed composition, not certified parity.
